# Tiny-KAN v1 正式结果独立审计（2026-08-11）

## 结论

审计结论为：

```text
PASS_ARTIFACT_INTEGRITY
KILL_TINY_KAN_KEEP_VALUE_ONLY
```

本轮没有发现会改变实验裁决的 artifact、配对、训练预算或统计错误。Tiny-KAN 在冻结的主比较上没有超过现有 `value_only` MLP，因此应按 Research Card 停止该方向，不运行 conditional zero-spline attribution、latency/memory gate 或 fresh confirmation。

本审计只读取：

- `experiments/tiny_kan_calibrator_v1/results/development_r1` 中的本轮正式结果；
- 已许可的 Abilene/GEANT `fit/source_dev/tune` 注册信息，其中只重新载入 `tune` 验证数据和 mask 身份；
- 当前 source-bound 实现和 checkpoint。

没有访问 sealed test，也没有访问旧 test cache。

另有两个必须保留的报告边界，但不属于实验错误：

1. 18 个结果记录的实际设备均为 `NVIDIA H800 80GB`，不能写成 H100。
2. KAN 的 B-spline basis 和 contraction 固定使用 FP32，而 MLP 保留原有 BF16 autocast lane。因此结果严格限定于这一个冻结实现，不能推广成“所有 KAN 均无效”。这也不构成推翻 kill 的理由：KAN 使用更稳健的数值路径后仍未超过 MLP。

## 独立审计方法

本次没有调用 `tiny_kan_calibrator_v1.adjudicate` 或 `result_io.verified_success` 来复读已有结论，而是在 `/tmp` 中使用独立只读脚本，从原始 JSON sufficient statistics 和 checkpoint 文件重新完成以下检查。

### 1. Closed grid 与 result identity

- 独立按 job-domain SHA-256 重算 18 个 job ID；
- 验证完整网格为 `2 datasets × 3 seed bundles × 3 methods = 18 jobs`；
- 每个 job 恰好存在一个 `attempt-001`，不存在 `attempt-002`；
- queue report 为 18 成功、0 失败、0 resumed success；
- 每个 result 和 manifest 都是 canonical JSON，且 result 文件为 write-once mode；
- 独立重算每个 manifest 的 result SHA，并验证 job、protocol、source SHA 全部一致。

### 2. Source、模型和 checkpoint

- 独立重算 launch plan 中每个 runtime file 的文件 SHA 与字节数；
- 独立使用 source-domain canonical hash 重算聚合 source SHA；
- 验证所有 result 都绑定同一个 source SHA；
- 独立重新实例化对应模型并核对 trainable parameter count；
- 独立重算 checkpoint identity SHA、checkpoint file SHA 和 tensor SHA；
- 将 18 个 checkpoint 全部 strict-load 到相应冻结模型，未发现 key、shape 或 tensor identity 漂移；
- 验证 `kan_value` 与 `kan_static` 完全参数匹配。

参数量为：

| 方法 | Trainable parameters |
|---|---:|
| `mlp_value` | 5,475 |
| `kan_value` | 5,539 |
| `kan_static` | 5,539 |

### 3. 数据、tune schedule 与方法配对

许可 loader 会在读取时重新验证 canonical parsed train/val arrays 的 pinned semantic SHA。审计进一步验证：

- Abilene tune：72 个 registered windows，每窗 `144 × 47 = 6,768` 个 K3 target；
- GEANT tune：15 个 registered windows，每窗 `462 × 47 = 21,714` 个 K3 target；
- 所有 stored window starts 与注册 tune schedule 完全一致；
- 独立重建每个 dataset × seed × mask 的 evaluation batch，并重新计算 mask-grid SHA；
- 独立重算每窗 truth sum 和 target count；
- 在三个方法之间逐值核对 window starts、target counts、truth sums、Linear error sums 和 mask-grid SHA。

以上身份均严格一致，没有发生换 mask、换窗口、换 denominator 或非配对比较。

### 4. 训练预算与 checkpoint selection

18 个任务均满足：

- 20 epochs；
- 每 epoch 64 physical batches；
- 每 epoch 16 optimizer updates；
- 总计 320 optimizer updates；
- 无 outcome-dependent early stop；
- selection cohort 为 `source_dev`，evaluation cohort 为已经消费过的 `tune`；
- 每个 stored best epoch 都是该任务 20 个 source-dev NMAE 中的真实最小值；
- best source-dev NMAE 与相应 epoch sufficient sums 的比值逐值一致；
- 每个任务恰好一个 epoch 被标记为 selected。

### 5. Point estimates 与 10,000-draw bootstrap

从每窗 `model_error_sum_per_window` 和 `truth_sum_per_window` 独立计算：

1. 在 dataset × seed 内对 structured masks 做 ratio-of-sums；
2. 对 seed 等权平均；
3. 对 Abilene/GEANT 等权平均；
4. 使用独立 `PCG64DXSM(seed=2026081107)`；
5. seed 有放回抽样，并对每个 dataset/seed 做 block length 4 的 circular window block bootstrap；
6. 运行固定 10,000 draws，并以 linear quantile 计算 2.5%/97.5% 区间。

独立结果与 `adjudication.json` 中所有 headline、dataset、mask、seed 和 bootstrap 数值逐值一致。

## 独立复算结果

### Tiny-KAN 相对当前 MLP incumbent

Structured equal-dataset relative gain：

| 95% block-bootstrap CI | **[-0.02892%, -0.00346%]** |
| Abilene | -0.03093% |
| GEANT | -0.00131% |

三个 seed bundle 的 equal-dataset structured gain 均为负：

| Seed bundle | Relative gain |
|---|---:|

Dataset × mask 结果：

| Cell | Relative gain |
|---|---:|

主效果不仅没有达到预注册的 `+1%` practical threshold，而且总体点估计和 bootstrap 区间均为负；两个 dataset headline 都不为正，三个 seed-bundle headline 也全部为负。

### KAN value conditioning 相对 KAN static

| 范围 | Relative gain |
|---|---:|
| 总体 | **+0.83094%** |
| 95% block-bootstrap CI | **[+0.69764%, +0.98428%]** |
| Abilene | +1.42749% |

两个数据集和三个 seed 的方向均为正。因此，`value_only` conditioning 在 KAN 参数化中确实携带有效信息；但 KAN 没有把该信息转化为超过现有 MLP 的收益。

## Gate 与裁决核验

主 KAN-over-MLP gate 中以下必要条件失败：

- structured gain `>= 1%`：失败；
- bootstrap lower bound `> 0`：失败；
- 两个 dataset 都为正：失败；
- 至少两个 seed bundle 为正：失败。

No-harm 条件和 KAN-value-over-static conditioning 条件通过，但 Research Card 要求所有 accuracy proceed conditions 同时通过。因此：

```text
KILL_TINY_KAN_KEEP_VALUE_ONLY
```

是唯一与预注册规则一致的裁决。

由于 accuracy gate 已失败，以下实验不应运行：

- zero-spline attribution；
- latency/peak-memory gate；
- fresh confirmation。

结果目录中也没有发现这些 conditional gate 的产物。

## Reviewer-safe claim boundary

可以写：

> 在保持观测信息、受约束输出方程、训练预算和近似参数量一致时，一次冻结的 edge-wise cubic B-spline KAN transplant 未能改善当前 5,475 参数 MLP calibrator。虽然 observation-conditioned KAN 明显优于同参数 static KAN，但现有证据不支持“MLP 函数族是当前性能瓶颈”。

不能写：

- “KAN 在 TM completion 中普遍无效”；
- “任何 spline parameterization 都不如 MLP”；
- “KAN 的 spline branch 已被单独证明无效”；
- “该结果是独立 test confirmation”；
- “Tiny-KAN 比 MLP 有实际收益”；
- 围绕 grid、order、width、depth 或 KAN variant 继续 outcome-driven sweep。

因为 accuracy gate 已失败，zero-spline attribution 按规则没有运行；因此 `kan_value > kan_static` 只能证明 observation conditioning 有效，不能把收益进一步归因给 spline branch。

## 最终研究判断

Tiny-KAN 本轮不是一个“差一点通过”的候选，而是没有提供任何替换当前 MLP incumbent 的 headroom：主效果约为零且略负，跨 dataset、seed 和 structured mask 的整体模式也不支持继续搜索。

因此应接受负结果，冻结 `value_only`，继续现有 CCF-C accuracy-efficiency 写作路线。不得借由更换 KAN 变体、grid 或宽度将这次 one-shot collision 重新变成开放式热门模块搜索。
