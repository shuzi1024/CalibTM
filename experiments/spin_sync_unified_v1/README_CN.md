# SPIN 编码驱动的 Direct＋Sync 统一模型

状态：2026-09-16 已完成两 WAN×两变体×两初始化的八条总 120 轮训练轨迹及统一推理成本测量。完整结果见 [本轮研究记录](../../analysis/spin_sync_unified_20260916/README_CN.md)。初始早停与后续接续属于同一轨迹。

该候选与四层原 SPIN、旧 SPIN 风格打分候选、481 参数输出修正器分别命名和保存，不继承它们的效果结论。

## 结构

可见流量、掩码与序列位置进入一层实际 SPIN 时空编码，得到32维上下文。其本流时间注意力、邻流时空注意力、位置编码、归一化和可见值 skip 使用现有 SPIN 实现。缺失输入在标准化前通过 `where` 清理；注意力源只允许真实可见位置。

Sync 用上下文投影出 K、V 和 Q，四个头各32维。每个目标的群组保留自身及原拟合图中的最多八个邻流；同一时刻的可见源使用同一个旧矩阵状态计算残差，再同步更新一次。K/Q 在各自32维头内归一化；隐藏和填充槽的 K/V 在投影后清零。SPIN 的空间图单独去 self，避免重复空间自边。

Direct 对每个方向直接读取同流最近两个可见原始数值。它用共享的 SPIN **位置**表示计算权重，保留加权值、槽位距离与可用性三个特征，然后投影至128维。没有使用 SPIN 最终预测作为输入。

前后方向分别以 `Sync_read + Direct_read` 融合，与上下文生成的 Q 一起送入单一解码器。模型全量从头联合训练，末层零初始化，初始输出等于全局拟合均值。所有数值路径使用同一个全局 fit 均值/标准差，不混用旧 Direct 的逐流归一化。

**前后只是扫描方向。** SPIN 上下文已读取整窗可见数据；前向状态可能间接包含后续可见观测，不能称为因果预测。任务仍是离线双向补全。窗口固定50槽；GEANT距离是已发布序列的行距离，物理时间和单位映射尚未核实。

## 最小对照

- `spin_sync_direct`：完整统一模型。
- `spin_direct_no_memory`：独立从头训练，保留同样的 SPIN、Direct、Q 和解码器，去掉 K/V 与矩阵扫描。

两者共有参数逐张量初始化完全一致。no_memory 没有闲置 K/V 参数，因此并非等参数量对照；它回答该组合中的 Sync 是否带来增量，不证明所有记忆规则的优劣。原 Direct＋Sync、四层 SPIN 和 Linear 作为既有参考；原四层 SPIN 的训练预算和深监督不同，不能仅凭该比较归因 Sync。

## 检查与运行

在完整 CalibTM 仓库及已有 PyTorch 环境中：

```bash
python -m experiments.spin_sync_unified_v1.checks
python -m experiments.spin_sync_unified_v1.runner --help
```

正式执行需要当轮用户批准的 GPU 时限，显式通过 `--deadline-unix` 传入；传入数值本身不构成资源授权。示例骨架：

```text
CUBLAS_WORKSPACE_CONFIG=:4096:8 CUDA_VISIBLE_DEVICES=<物理GPU编号> \
.venv/bin/python -m experiments.spin_sync_unified_v1.runner \
  --dataset geant --variant spin_sync_direct --seed 41001 \
  --device cuda:0 --deadline-unix <本轮已授权的截止时间>
```

先加 `--smoke` 做独立的两步拟合输入和恢复检查，再执行正式训练；恢复已有任务需 `--resume`。
默认新输出为 `outputs/spin-sync-unified-20260916-v1/{dataset}/{variant}/seed41001/`。

沿用原512个拟合窗口与开发范围、三种20%观测条件、数据顺序51001/训练掩码61001/开发掩码71001。训练为 AdamW 0.001、权重衰减0.0001、缺失原始L1/fit均值、batch8、最多120轮，至少25轮且从第16轮累计10轮未改善时早停。目标图全量编码，SPIN内部按32个节点分块；本轮不读取后续历史gate，不调新观测率。

每轮训练和开发评估完成后原子保存模型、优化器、RNG和最佳状态；中断未提交的一轮时，恢复从上一完整轮重放。完成结果必须重载最佳权重后重新评估。截止前一分钟停止新批次，保留恢复点，不将未完成结果标为完成。

当前代码只实现这一套结构及一个关键对照，没有沿用上轮冻结主干预测缓存；联合训练中该缓存会过时。

外部时限：服务器已有 GNU timeout，可在每次获批的 runner 命令外加进程组截止保护：在授权截止前60秒发送TERM，到截止时KILL。只包裹本次子进程，不终止其他GPU任务。smoke与train必须分别启动，检查SMOKE.json中的耗时和显存后才决定正式训练；本轮任务已结束。这里的命令是原执行接口说明；重新运行需要对应的数据、历史注册记录与新资源安排。
