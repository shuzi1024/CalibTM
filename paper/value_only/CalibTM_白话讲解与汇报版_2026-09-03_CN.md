# CalibTM 白话讲解与汇报版

这份材料不是论文，也不是审计报告。它的目标是让第一次听这项工作的人能听懂，也让汇报者自己真正理解每一步为什么存在。

> 汇报口径：导师和师兄已经了解 ARI-LLM，因此 `TM`、`OD flow`、`Linear`、`Flow2Vec/LSTM`、`LLM`、`AR`、`mask`、`NMAE`、`seed`、`Abilene/GEANT` 等基础术语可以直接保留。本文的“白话”主要是去掉新出现的审计黑话和过度包装，不是把已有专业概念全部改成生活比喻。

---

## 0. 先只记住这个生活类比

想象有一本交通日记。

- 每一行记录一条路线，例如“城市 A 到城市 B”的流量；
- 一行原本应该有连续 50 个时间点；
- 但由于档案不完整，现在只剩下 3 个真实数字，另外 47 个位置都空了；
- 我们的任务是根据这 3 个真实数字，把这一行尽量补完整。

最简单的办法是拿直尺连接这三个点。这就是 **Linear interpolation，线性插值**。

CalibTM 的想法不是把这条直线扔掉，让一个大模型重新画整条曲线，而是：

> 先用直尺画出大致曲线，再让一个很小的模型在规定范围内修一修；三个真实点最后原样抄回，绝对不能改。

这就是整篇论文。后面的实验都在回答三个问题：

1. 这种“小修正”是否真的比直线更准？
2. 改善是否只是因为多加了一个神经网络？
3. 为这一点改善付出的计算代价是否合理？

---

## 1. 我们究竟在补什么

### 1.1 什么是 Traffic Matrix

Traffic Matrix，简称 TM，可以理解成网络中的“流量账本”。

例如网络里有北京、上海、广州三个节点，那么会有：

- 北京到上海的流量；
- 北京到广州的流量；
- 上海到北京的流量；
- 其他所有起点—终点组合。

每一个“从某个起点到某个终点”的组合叫一条 **OD flow**。OD 就是 Origin–Destination，起点—终点。

我们的数据把很多条 OD flow 排在一起，每条 flow 又有一串随时间变化的数字。这些数字合起来就是随时间变化的 Traffic Matrix。

### 1.2 为什么会缺数据

真实网络档案可能因为维护、采集程序中断、传输失败等原因出现空档。但当前论文没有拿到一份“真实 WAN 流量矩阵恰好缺失、同时又知道缺失真值”的理想数据。

因此主实验采用的是：

1. 从完整历史数据中取出长度为 50 的窗口；
2. 人工只留下 3 个位置；
3. 把其余 47 个位置藏起来；
4. 让方法根据 3 个可见点恢复 47 个隐藏点；
5. 因为原始数据完整，所以可以比较恢复值与真值。

这叫 **artificial thinning，人工抽稀**。它适合公平比较方法，但不等于已经复现真实运营中的缺失过程。

### 1.3 这是预测未来吗

不是。

这是修复已经发生完的历史档案，所以补中间空白时，可以同时看它左边和右边的真实点。论文把它叫 offline repair 或 offline smoothing。

一个非常重要的边界是：

> 这项工作不能说成预测明天的流量，也不能说成实时在线恢复。

## 2. Linear 是什么，为什么说它“很强”

### 2.1 Linear 怎样补数据

假设三个已知点是：

```text
时间：  0       20       49
流量： 10       30       20
```

Linear 会做两件事：

- 在时间 0 到 20 之间，从 10 均匀增加到 30；
- 在时间 20 到 49 之间，从 30 均匀下降到 20。

如果第一个已知点不是时间 0，那么更左边没有第二个点可供连线，当前实现就先一直使用最靠近的那个已知值。最右边同理。

它的优点很明显：

- 不用训练；
- 几乎不要计算资源；
- 只使用真实可见点，不偷看隐藏真值；
- 画出的线必然经过真实锚点；
- 在变化比较平缓的时间段里通常很合理。

### 2.2 “Linear 很强”究竟是什么意思

这里不是说所有网络流量都服从直线，也不是说 Linear 永远最好。

准确含义是：

> 在当前 Abilene/GEANT、长度 50、只保留 3 个点、允许同时使用左右锚点的实验中，Linear 已经是一个很难大幅超过的零训练基线。

证据是：

- CalibTM 在 A/G structured masks 上只比 Linear 好约 1.52%；
- 另一种传统曲线插值 PCHIP 反而比 Linear 差约 1.09%；
- 把 random、internal-block、two-burst 三类注册 mask 都纳入，在每个网络内合并、对 3 个 seed 等权，再让 A/G 各占 50% 时，Linear NMAE 为 0.227600，ARI 为 0.229020，两者非常接近；
- 但 Abilene 上 ARI 更好，GEANT 上 Linear 更好，所以不存在“Linear 到处赢”。

在 BRAIN 上 Linear 的 NMAE 高达 0.928，说明这个任务的绝对恢复质量仍然很差。因此 BRAIN 只能说明 Linear 是一个明确、可用的起点，不能说它已经把问题解决得很好。

一句最安全的汇报说法是：

> Linear 不是普遍最优，但在我们固定的极端稀疏协议中，它是一个有竞争力而且几乎零成本的起点。

## 3. 原来的 ARI-LLM 大致在做什么

不看数学细节，可以把 ARI-LLM 理解成下面五步：

1. 先用 Linear 把每条残缺 flow 初步填满；
2. 用 Flow2Vec/LSTM 把一整条 flow 压缩成一个向量；
3. 把不同 flow 当成一串 token 交给 GPT-2，让它们互相交换信息；
4. 用 decoder 输出补全结果；
5. 分多个阶段反复填充，逐步完成整张矩阵。

它的好处是表达能力强，可以利用不同 flow 之间的关系。代价是：

- 模型大；
- 推理过程长；
- 需要更多显存和时间；
- 在不同网络上不一定稳定优于简单方法。

CalibTM 并不是在 ARI 后面再挂一个小模块。它把上述 Flow2Vec、GPT 和多阶段重建主干整体拿掉，只保留“Linear 起点 + 小幅校准”。

但必须注意：

> 当前论文没有证明 ARI 的 LLM、Flow2Vec 或多阶段过程无用。

旧实验只能方向性地说明：有强 Linear 起点时，GPT 与 no-LLM 有时差别很小；去掉这个起点后，LLM 在一些设置里又明显有用。因此更准确的认识是：大模型能否发挥作用，和它拿到的初始信息、训练方式、数据集都有关系。

## 4. CalibTM 到底做了什么

### 4.1 第一步：先画 Linear 草图

三个真实点先决定一条 Linear 曲线。论文有时把它叫 scaffold，直译是“脚手架”或“骨架”。口头汇报直接说：

> Linear 先给出一条初始曲线。

### 4.2 第二步：小网络只修一点，不许推倒重画

CalibTM 有一个非常小的 MLP，总共 5,475 个参数。

你不需要在汇报里讲 16 个输入槽或每层多少维。只要知道：在真正缺失的位置，小网络看到的主要变化信息就是当前 Linear 给出的数值，外加少量由已知点计算出来的尺度信息。

因此比“observation-conditioned”更容易理解、更准确的说法是：

> 这个小网络主要根据当前的 Linear 草图决定怎样小幅修正。

### 4.3 内部空档和两端空档分开处理

一条曲线的空白有两种：

1. **内部空档：** 左右两边都有真实点；
2. **边界空档：** 只在一侧有真实点，例如第一个真实点之前的空白。

CalibTM 分别学习两种小修正：

- 对内部位置，在左右锚点连线附近微调；
- 对边界位置，在最近锚点附近整体上下移动一点。

当前边界处理有一个明确限制：同一侧的一整段边界空白会得到相同修正，不会随着离锚点越来越远而逐渐变化。汇报时如果没人追问，不必主动展开；若被问模型表达能力，就诚实说明这是当前极简设计的限制。

### 4.4 什么叫“有界”

有界就是给小网络装护栏。

它不能随意把一个值从 10 改成 1000。代码使用 `tanh` 把网络输出压在有限范围内，再根据两个锚点的差异和当前 flow 的观测尺度决定最多能改多少。

这带来两个直观性质：

- 修正不会毫无限制地爆炸；
- 模型的任务是“修正 Linear”，而不是重新生成任意曲线。

但现有实验只证明这些护栏在运行中经常实际参与，并没有用完全匹配的无界模型证明“有护栏一定比没护栏更准”。因此不能把 boundedness 的必要性说成已经得到因果证明。

### 4.5 最后两道保险

1. 三个真实观测点最后原样复制回来，模型永远不能改它们；
2. 如果缺失位置预测成负流量，就截到非负范围。

这就是论文里的 hard-copy anchors 和 nonnegative projection。口头直接说“真点绝不改，流量不能为负”即可。

## 5. 为什么需要 Context-Free 这个公平对照

假如我们只比较：

```text
Linear              vs              Linear + 小网络
```

即使右边更好，也有人会问：是不是只要随便多加 5,475 个参数就会更好？

因此我们做了一个“蒙眼校图员”：

- 它和 CalibTM 参数量一样；
- 初始化一样；
- 训练次数一样；
- 外面的 Linear 和修正护栏也一样；
- 唯一区别是，小网络看不到当前样本的 Linear 条件，只能学一套固定动作。

代码里它叫 `static_zero`，论文里叫 Context-Free Calibrator。口头最好叫：

> 同规模但看不到当前草图的公平对照。

如果 CalibTM 比它好，说明：

> 让小网络根据当前 Linear 草图决定修正，确实比对所有样本机械地使用同一套修正更有价值。

这个对照不能证明：

- Linear 一定不可缺少；
- 有界一定优于无界；
- 内部/边界分开一定是最佳结构；
- 小网络优于所有其他模型。

它只回答一个很干净的问题：**“看当前草图”是否有增量价值。**

## 6. 实验指标怎样读

### 6.1 NMAE

NMAE 是预测误差除以真实流量总量。你只需要记住：

> NMAE 越低越好。

例如：

- Linear NMAE = 0.240；
- CalibTM NMAE = 0.236。

CalibTM 的误差更低。

### 6.2 “提升 1%”不是 NMAE 减少 0.01

论文里的提升通常是相对比例：

```text
(对照误差 - CalibTM误差) / 对照误差
```

所以从 0.240 降到 0.236，绝对少了约 0.004，但相对改善约 1.7%。

汇报时最好同时表达：

> 相对提升大约 1%，绝对 NMAE 只下降几个千分点，效果稳定但幅度不大。

这比只报四位小数更诚实，也更容易让老师判断价值。

### 6.3 Seed、mask 和置信区间

- **Seed：** 同一个模型换不同随机初始化再训练，检查结果是不是碰巧；
- **Mask：** 决定 50 个位置里哪 3 个被留下；
- **置信区间：** 用重复抽取时间块的办法，估计“如果换一批时间段，改善可能落在哪个范围”。

如果 95% 区间全部大于 0，可以说当前统计分析支持改善为正。但它不等于 95% 保证未来任何网络都改善。

## 7. 三个最重要的结果怎样理解

| 数据 | 比同规模蒙眼对照好多少 | 比 Linear 好多少 |
|---|---:|---:|
| Abilene | +1.34% | +1.89% |
| GEANT | +0.74% | +1.15% |
| A/G structured（seed / dataset 等权） | **+1.04%** | **+1.52%** |
| BRAIN | **+1.14%** | **+3.26%** |

### 7.1 A/G 说明什么

Abilene 和 GEANT 是开发过程中使用的两个 WAN 数据集。这里的主结果只汇总 internal-block 和 two-burst 两类成段缺失：每个 dataset×seed 内先合并两类 mask，再对 3 个 seed 和 A/G 等权。两者、三个随机种子、主要结构化缺失方式总体都给出同方向结果。

它说明改善不是只存在于一个 seed 或一个网络里。

但这两个数据集已经参与方法开发，所以它们不是完全独立的新测试。

### 7.2 BRAIN 说明什么

在 CalibTM 结构、超参数和模型选择规则冻结后，又使用了 SNDlib BRAIN。BRAIN 使用自己的 fit/source-dev 训练并选择 checkpoint；6 个 checkpoint 登记冻结后，才打开 28-window confirmation。这不是把 A/G 权重直接 zero-shot 到 BRAIN。

- 相比同规模公平对照好 1.14%；
- 相比 Linear 好 3.26%；
- 三个 seed、两种结构化缺失均同向。

这比继续切 A/G 的新子集更有价值，因为它是另一个 WAN 和不同数据生成过程。

但也有三项限制：

- BRAIN 的 OD demand 不是直接采集，而是从链路测量经过优化反演得到；
- 使用的是整周公开的 flow 列表；
- 最终确认只有 28 个 50 分钟窗口，约一天。

### 7.3 为什么说改善“小而稳定”

1% 左右不是惊人的精度飞跃。但 Linear 本身已经非常便宜且有竞争力，CalibTM 仍能用 5,475 个参数在三个 WAN 上稳定再降一点误差。

这篇论文的价值不是“刷新所有榜单”，而是：

> 在一个强而便宜的基线上，用非常小的 learned cost 换到可重复的小幅改善。

## 8. ARI 和 ImputeFormer 的结果为什么不能只看平均值

在 A/G 全部 masks 上：

| 方法 | A/G 平均 NMAE，越低越好 |
|---|---:|
| CalibTM | 0.224009 |
| Linear | 0.227600 |
| ARI | 0.229020 |
| ImputeFormer adapter | 0.267572 |

只看平均值，好像 CalibTM 最好。但拆开后：

- Abilene：ARI 比 CalibTM 好约 1.13%，ImputeFormer 还要更好；
- GEANT：CalibTM 又明显好于两者。

所以正确结论不是“我们打败了两个大模型”，而是：

> 大型模型在不同网络上的表现变化很大；CalibTM 寻找的是较稳定、较便宜的折中位置。

这也是为什么主表必须保留每个数据集，而不能只显示平均值。

## 9. 速度与模型大小怎样解释

### 9.1 模型大小

- CalibTM：5,475 参数；
- ARI：约 8,478 万总参数，其中约 3,201 万可训练；
- CalibTM checkpoint：约 27 KB；
- ARI checkpoint：约 355 MB。

这说明两者的 learned-model 规模不在一个数量级。

### 9.2 GPU 和 CPU 结果

在当前固定实现里，CalibTM 比 ARI 和 ImputeFormer 快很多、占用更少。

但 Linear 仍明显比 CalibTM 快。例如 CPU 单样本下，Linear 大约快 16–23 倍。

因此最准确的图像是：

```text
Linear：最便宜，精度略低
CalibTM：成本增加一点，精度稳定提高一点
ARI / ImputeFormer：learned-model 成本大得多，精度又高度依赖数据集
```

速度实验测的是当前代码管线，不代表经过极致优化后的架构理论速度。口头不要背所有倍率；主汇报只需要说“CalibTM 比大型 learned pipeline 轻很多，但 Linear 仍是最低成本”。

## 10. 后续补做的分析分别在回答什么

这些分析不要在主汇报逐个报数字，只要知道它们各自排除了什么怀疑。

### 10.1 时间块统计

怀疑：相邻时间点很像，会不会把很多相关样本误当成独立样本，导致区间虚假地很窄？

处理：按约一天、两天的连续时间块一起重采样，并让不同方法、mask、seed 使用同一个时间块。

结果：A/G 的改善区间仍然全部为正。

边界：BRAIN 只有约一天，无法证明长期稳定。

### 10.2 冻结权重跨 WAN 使用

怀疑：每个网络都必须重新训练，是否完全不能迁移？

处理：拿在 A、G、BRAIN 中一个网络训练好的权重，不更新权重，直接放到另一个网络。

结果：六个方向的 structured 结果都保持正改善。

边界：目标网络仍使用了它自己的观测归一化规则，而且这些数据此前已经看过，所以只能作为描述性证据，不能叫全新的零样本测试。

### 10.3 RIPE availability-shape replay

怀疑：人工缺失形状会不会完全脱离真实采集过程？

处理：从三次官方 RIPE RIS 维护事件中提取“哪些时间槽有文件、哪些没有文件”，把这个 0/1 缺失形状应用到 A/G 完整流量上。

结果：相比 Linear 36/36 为正，相比公平对照 35/36 为正。

边界：真实的只是 BGP collector 是否产生文件，流量真值仍来自 A/G；它不是“真实 TM 故障恢复”。

### 10.4 Bounds 诊断

怀疑：所谓“有界”是不是只写在公式里，实际网络输出很小，护栏根本不起作用？

处理：统计修正用了允许范围的多少、非负截断是否触发。

结果：内部修正常用约 60% 左右的允许范围，边界修正常用约 82%–93%，非负截断也会触发。因此约束实际参与运行。

边界：这仍不能证明有界模型比同参数无界模型更准。

## 11. 导师所说的 auto-research 到底指什么

这里的 auto-research 不是“使用 AI 做研究”本身，而是一种危险的研究方式：

```text
看到结果不好
→ 再加一个模块
→ 再换一种 loss
→ 再挑一个 mask
→ 再找一个局部正数
→ 最后从大量尝试里挑最好看的故事
```

这样会产生两个问题：

1. 不知道改善究竟来自什么；
2. 试得越多，偶然撞上正结果的概率越大。

这两个月真正重要的纠偏是：

1. 明确一个固定问题，而不是继续问“还有什么模块可以加”；
2. 对复杂路线设置停止标准，失败后真的停止；
3. 冻结 CalibTM，不因后验诊断再加 edge 特征、删 head 或调 bound；
4. 区分开发数据和冻结后的 BRAIN confirmation；
5. 新增工作主要检查统计、边界、迁移和成本，而不是寻找下一个赢家。

也要诚实：CalibTM 不是一开始就由真实 outage 理论推导出来的。它先在早期系统收缩中成为幸存的最小算子，后来才经过 problem-first 审计和新数据确认。汇报可以说“研究最终收敛到这个问题”，不要说“我从一开始就按这个问题设计了它”。

## 12. 这篇论文真正可以说什么

推荐的完整主张：

> 在长度 50、每条 flow 只有 3 个可信观测、允许离线双向修复且不使用 topology/routing/flow identity 的设置中，Linear 是一个有竞争力的零训练起点。CalibTM 不重新自由生成整条曲线，而只在 Linear 周围做锚点保持、幅度受限的小修正。它相对 Linear 和同规模公平对照取得小而稳定的改善，并形成介于 Linear 与大型 learned models 之间的精度—成本折中。

这已经是一条完整而诚实的论文主张。

## 14. 真正适合口头汇报的六页

### 第 1 页：问题

标题：**只有 3 个真实点时，是否需要大模型重画整条流量曲线？**

讲法：

> 我研究的是历史流量档案修复。每条曲线有 50 个位置，但只留下 3 个可信点。因为是离线修复，我们能同时看到缺口左右的点。最简单的 Linear 已经能连出一条合理初始曲线，所以核心问题不是从零生成，而是有没有必要为剩余误差付出大型模型的成本。

### 第 2 页：方法

标题：**先用 Linear 打底，再让小模型在护栏内修一点**

只画五个框：

```text
3个真点 → Linear初始曲线 → 小幅内部/边界修正 → 真点原样抄回 → 完整曲线
```

讲法：

> CalibTM 只有 5,475 个参数。它不自由生成 47 个缺失值，而是根据 Linear 草图做有限修正；真实点永远不改，预测流量不允许为负。

### 第 3 页：公平对照

标题：**改善不是因为随便多加了一个网络**

讲法：

> 我做了一个参数量、初始化和训练次数完全相同的对照。区别只是这个对照看不到当前 Linear 草图，只能对所有样本使用固定修正。CalibTM 比它更好，说明根据当前草图决定修正有真实增量。

### 第 4 页：结果

标题：**三个 WAN 上都是小幅、同方向改善**

主表只放 A、G、BRAIN 三行和两个 gain 列。

讲法：

> A/G 平均相对公平对照改善 1.04%，相对 Linear 改善 1.52%；冻结后在 BRAIN 分别改善 1.14% 和 3.26%。幅度不大，但跨网络、随机种子和主要缺失形状总体一致。

### 第 5 页：成本与诚实边界

标题：**它不是最低成本，而是中间的折中点**

讲法：

> Linear 最便宜；CalibTM 多花少量 learned cost 换取稳定小幅改善；ARI 和 ImputeFormer 成本明显更高，而且精度对网络更敏感。所有主缺失方式仍是人工生成，这是当前最重要的现实性限制。

### 第 6 页：研究怎样从发散变成收敛

标题：**停止模块搜索，进入论文写作**

讲法：

> 这两个月最重要的变化不是多试了多少模型，而是建立停止规则：复杂路线没有通过就停止；CalibTM 冻结后只做外部确认、统计和成本检查，不再根据结果继续加模块。下一步是成稿与公平 baseline，而不是继续搜索结构。

## 15. 一段可以直接照着讲的三分钟版本

> 我研究的是历史网络流量档案修复。可以把每条流量曲线想成 50 个时间点，但现在只剩 3 个可信数字，其他 47 个都缺失。因为修的是过去的档案，我们能同时使用缺口左右的真实点。最简单的做法是拿直尺连接这些点，也就是 Linear interpolation。
>
> 我发现，在当前极端稀疏设置中，Linear 已经是一个很有竞争力、几乎没有计算成本的起点。因此我的问题不再是怎样用更大的模型重新生成整条曲线，而是：能不能只让一个很小的模型在这条直线附近做有限修正？
>
> CalibTM 就是这样一个模型。它只有 5,475 个参数，分别对两个真实点中间的空档和曲线两端的空档做小幅调整。调整有明确上限；三个真实观测最后会被原样复制回来；负流量也不会被输出。因此它更像一个带护栏的校图员，而不是自由画图的生成器。
>
> 为了确认改善不是因为随便多加了一个网络，我做了一个同参数、同初始化、同训练预算的公平对照。这个对照保留相同的 Linear 和外层修正规则，但小网络看不到当前样本的 Linear 草图，只能学习一套固定动作。A/G 上 CalibTM 相对这个对照平均改善 1.04%，相对 Linear 改善 1.52%。模型和规则冻结后，在第三个 WAN BRAIN 上分别改善 1.14% 和 3.26%，三个随机种子和两种结构化缺失都同方向。
>
> 这个结果不是巨大精度提升。它的意义是，在一个已经很强的零训练基线上，只增加一个 5,475 参数的小模型，能在三个 WAN 上稳定再减少一点误差。GPU 和 CPU 测量也表明它比 ARI 和 ImputeFormer 当前管线轻很多；不过 Linear 仍然是最便宜的方法，所以 CalibTM 的定位是中间的精度—成本折中点。
>
> 我也保留几个明确边界：主实验仍是人工缺失；BRAIN 不是直接测量 OD；现有对照只证明根据当前 Linear 草图进行修正有价值，还没有证明有界结构一定优于所有无界模型。因此这两个月的关键进度不是继续加模块，而是停止发散搜索，冻结一个有正证据的最小方法，并把它的有效范围和不足都弄清楚。下一步是正式成稿，而不是继续试新结构。

## 16. 哪些术语保留，哪些换成简单说法

### 16.1 可以直接保留的 ARI-LLM 基础术语

以下词在主汇报中可以正常使用，不需要每次重新解释：

- TM、OD flow；
- observed / missing、mask、observation rate；
- Linear、PCHIP；
- Flow2Vec、LSTM、GPT/LLM；
- AR、coarse-to-fine；
- NMAE、seed；
- Abilene、GEANT；
- training、validation、checkpoint、baseline、ablation。

第一次出现 `K=3,T=50` 时，只需补一句“每条长度 50 的 OD flow 只保留 3 个观测”。

### 16.2 这次新增术语的简单说法

| 论文术语 | 白话含义 | 汇报时建议说法 |
|---|---|---|
| K=3, T=50 | 50 个位置只留下 3 个真实值 | 每条长度 50 的 OD flow 只保留 3 个观测 |
| offline smoothing | 修复已结束的历史，可看左右两侧 | 离线历史档案修复，不是预测未来 |
| artificial thinning | 从完整数据里人工藏掉大部分位置 | 人工制造缺失，便于知道真值 |
| canonical Linear | 固定规则的线性插值版本 | 用同一把直尺连接真点 |
| scaffold | 为后续修正提供的初始结果 | Linear 初始曲线/草图 |
| calibrator | 不重画，只修正已有结果的模型 | 小型校图员 |
| bounded calibration | 修正幅度有上限 | 在护栏内小幅修正 |
| anchor preservation / hard-copy | 已知真实点绝不允许改变 | 最后把真点原样抄回 |
| nonnegative projection | 不允许负流量 | 负值截回非负 |
| internal / edge | 两锚点之间 / 最左最右边界 | 中间空档 / 两端空档 |
| Context-Free Calibrator | 同规模但看不到当前条件的控制模型 | 同规模的蒙眼公平对照 |
| matched control | 除研究因素外尽量完全相同的对照 | 公平对照 |
| metric-matched ARI | 按同一指标和任务口径重新训练的 ARI | 在相同评分规则下比较的 ARI |
| structured mask | 连续块或两段缺口等有形状的缺失 | 不是随机散点的成块缺失 |
| seed | 训练随机性的不同起点 | 换随机初始化重复训练 |
| NMAE | 按真实流量规模归一化的绝对误差 | 越低越好的相对误差 |
| relative gain | 相对对照减少了多少比例的误差 | 比对照少了百分之多少误差 |
| confidence interval | 重采样后效果可能落入的范围 | 换时间段后结果的稳定范围 |
| bootstrap | 反复重抽数据估计不确定性 | 用很多次时间块重抽检查稳定性 |
| frozen checkpoint | 模型权重已经固定，不再改 | 模型封存后再测试 |
| confirmation | 方法冻结后在新数据上的验证 | 定型后换一个网络再考一次 |
| post-gate descriptive | 看过主结果后做的解释性分析 | 只能帮助理解，不能当全新证明 |
| cross-WAN transfer | 一个网络训练的权重拿到另一个网络 | 不重新训练，换网络使用 |
| operating point | 精度、成本与限制之间的一种选择 | 精度—成本折中点 |
| dataset heterogeneity | 不同数据集上的结论不完全相同 | 换网络后输赢会反转 |
| provenance | 数据从哪里来、怎样产生 | 数据来源和加工过程 |
| LP-inverted OD | 从链路数据通过优化问题反推出 OD | 不是直接测量，是从链路流量算出来的 |
| flow identity | 模型知道当前是哪一条具体 flow | 记住每条路线的身份 |
| topology / routing | 网络连接关系 / 流量经过哪些路径 | 网络地图和走法 |
| Pareto / accuracy–efficiency | 用多少成本换多少精度 | 精度—成本折中 |

### 16.3 主汇报里建议完全不说的词

`source-dev`、`historical gate`、`payload capability`、`registry`、`source hash`、`dataset-equal estimand`、`outer/inner bootstrap`、`evidence consumed`、`P_query`、`I_placement`、各实验目录代号。这些只在别人追问实验治理或复现时回答。

## 17. 你真正需要记住的十句话

1. 我补的是历史档案，不是预测未来。
2. 每条曲线 50 个点，只留下 3 个真点。
3. Linear 就是先用直尺把真点连接起来。
4. 在当前设置里 Linear 很有竞争力，但不是普遍最优。
5. CalibTM 不推倒重画，只在 Linear 附近小幅修正。
6. 真点最后原样抄回，流量不能为负。
7. 公平对照证明“看当前 Linear 草图”确实有增量价值。
8. A/G 平均改善约 1%，BRAIN 也保持同方向，效果小但稳定。
9. Linear 最便宜；CalibTM 是它和大型模型之间的折中点。
10. 这两个月的关键进度是停止模块搜索并形成论文闭环。
